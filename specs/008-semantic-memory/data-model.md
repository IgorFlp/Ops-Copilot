# Data Model: Semantic Memory

## Memory

Represents one durable fact saved by a single user.

| Field | SQLite type | Rules |
|-------|-------------|-------|
| `id` | `INTEGER PRIMARY KEY` | Generated by SQLite; stable identifier used to forget one fact. |
| `user_id` | `TEXT NOT NULL` | Required owner identifier; every read, duplicate check, and delete is scoped by this value. |
| `fact` | `TEXT NOT NULL` | Non-empty fact supplied to the remember operation. |
| `embedding` | `BLOB NOT NULL` | Exactly 384 little-endian Float32 values (1,536 bytes) from the selected embedding model. |
| `created_at` | `TEXT NOT NULL` | UTC ISO timestamp assigned when inserted. |

The table name is `memories`. Add an index on `user_id` for scoped lookup. The
application validates vector length and finite numeric values before writing
and after reading a BLOB; invalid persisted vectors are reported as errors.
There is no user foreign key because the current application has no users
table. Duplicate facts are not enforced by a text uniqueness constraint:
similarity-based duplicate handling is a per-user service rule.

## Relationships

- One user identifier owns zero or more memory rows.
- A memory is owned by exactly one `user_id`.
- The existing chat request is associated with a `userId`; that identifier
  scopes recall before any returned facts are included in strategy context.
- No persistent relationship is added between memories and conversation
  records; memories are durable user facts, not conversation messages.

## Validation and state behavior

- `remember(userId, fact)` requires a non-empty owner and fact. Compare the
  normalized incoming vector to only that user's stored vectors. If any score
  is greater than `0.92`, preserve the existing row and insert nothing;
  otherwise insert one new row.
- `recall(userId, query)` requires a non-empty owner and query. Score that
  user's vectors by dot product, discard scores at or below `0.3`, sort
  qualifying results from highest to lowest, and return at most three.
- `forget(userId, memoryId)` deletes only a row matching both identifiers.
  An absent match is reported as not found; it must not reveal whether the
  identifier belongs to another user.
- There are no automatic expiry or replacement transitions. A row remains
  until its owner explicitly forgets it.
